# Прокси к Supabase (api.cornflow.me)

Зачем: у части российских провайдеров адреса `*.supabase.co` не открываются
или открываются минутами. Сайт (GitHub Pages) при этом грузится, но
регистрация, вход и данные — нет. Решение: свой домен на российском сервере,
который пересылает запросы в Supabase. Браузер ходит на `api.cornflow.me`,
а до `supabase.co` достаёт уже сервер.

## 1. Сервер

Любой VPS в России с Ubuntu 22.04/24.04: 1 ядро, 1 ГБ памяти хватит
(Timeweb Cloud, Selectel, REG.RU, Beget, Yandex Cloud — ~150–400 ₽/мес).
Публичный IPv4 обязателен.

## 2. DNS

У регистратора домена `cornflow.me` добавьте запись:

| Тип | Имя | Значение      |
|-----|-----|---------------|
| A   | api | IP сервера    |

Подождите 5–30 минут, проверка: `nslookup api.cornflow.me` показывает IP сервера.

## 3. Установка (5 минут)

Зайдите на сервер по SSH (данные выдаёт хостинг) и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/bin985100-sys/cornflow/main/deploy/setup.sh | sudo bash -s -- api.cornflow.me ваш@email
```

Скрипт сам проверит DNS и доступ к Supabase, выпустит сертификат
Let's Encrypt (продлевается автоматически) и включит nginx.
В конце должно быть `ok` и `HTTP 401` — это норма (запрос без ключа).

## 4. Переключить приложение

В корне репозитория создайте файл `.env.production` с одной строкой:

```
VITE_SUPABASE_PROXY_URL=https://api.cornflow.me
```

и запушьте — GitHub Pages и Vercel пересоберутся сами. Адрес прокси не секретный,
ключи (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) остаются в переменных Actions
как были. Откат — удалить строку и запушить.

Пользователей не разлогинит: имя сессии в браузере закреплено за проектом,
а не за адресом.

## 5. Проверка

Откройте `https://cornflow.me/diag.html` **без VPN** с телефона на мобильном
интернете — все четыре строки должны быть «нормально».

## Supabase: что поправить один раз

- **Лимиты входа** считаются по настоящему IP пользователя: прокси передаёт его
  в `X-Forwarded-For`, Supabase это учитывает (проверено по логам Auth).
- **Вход через Google** на «закрытых» сетях всё равно не заработает:
  Google возвращает пользователя на `wlfwwclmkecutiznnwtt.supabase.co/auth/v1/callback`.
  Почта+пароль и школьные логины работают через прокси полностью.
  Полное решение — платная опция Supabase *Custom Domain* (`api.cornflow.me`
  становится официальным адресом проекта, и его же указывают в Google Cloud).
- **Письма** (сброс пароля) содержат ссылку на `supabase.co` — на закрытых
  сетях она тоже не откроется. Сброс через администратора школы работает.

## Обслуживание

- Логи: `sudo tail -f /var/log/nginx/access.log /var/log/nginx/error.log`
- Перезапуск: `sudo systemctl reload nginx`
- Обновить конфиг: ещё раз выполнить команду из шага 3
- Откатиться: вернуть `VITE_SUPABASE_URL=https://wlfwwclmkecutiznnwtt.supabase.co` и пересобрать.
