# CornFlow

Агрегатор учебных материалов для преподавателей и учеников: конспекты, PDF, презентации,
видео, ссылки и задания живут в одном пространстве — цветными карточками, с тегами,
поиском, дедлайнами и календарём.

**Стек:** React 18 + TypeScript + Vite + Tailwind CSS + Supabase (Auth / PostgreSQL + RLS / Storage / Realtime).

---

## Быстрый старт

```bash
npm install
npm run dev
```

Откроется http://localhost:5173 — вас встретит **лендинг**. Дальше «Начать бесплатно» →
регистрация по почте (или через Google, см. ниже) → приложение.

Демо-контента нет: после регистрации создаётся одно пустое пространство и базовый
словарь тегов. Всё остальное вы наполняете сами.

### Куда что ведёт

| Маршрут | Что это |
|---|---|
| `/` | лендинг с описанием продукта |
| `/auth` | вход и регистрация (`?mode=signup` открывает регистрацию) |
| `/app` | дашборд, требует авторизации |
| `/app/library`, `/app/assignments`, `/app/tasks`, `/app/calendar`, `/app/starred`, `/app/progress`, `/app/settings` | разделы приложения |
| `/join/:code` | вход в чужое пространство по ссылке-приглашению |

Закрытые маршруты без сессии уводят на `/auth?next=…` и возвращают обратно после входа.

## Подключение Supabase

Без ключей приложение работает в **локальном режиме**: аккаунт, пространства, материалы
и задания хранятся в этом браузере (записи — в `localStorage`, файлы — в `IndexedDB`),
переживают перезагрузку и закрытие вкладки. В настройках есть выгрузка и восстановление
резервной копии одним JSON-файлом.

Чтобы данные жили на сервере и открывались с любого устройства:

1. Создайте проект на [supabase.com](https://supabase.com).
2. В **SQL Editor** выполните `supabase/migrations/0001_init.sql`, затем `supabase/seed.sql`.
   Скрипт создаёт все таблицы, индексы, триггер профиля, политики RLS, приватный бакет
   `materials` с политиками доступа и добавляет таблицы в публикацию realtime.
3. Скопируйте `.env.example` → `.env` и заполните:

   ```env
   VITE_SUPABASE_URL=https://<project>.supabase.co
   VITE_SUPABASE_ANON_KEY=<anon key>
   ```

4. `npm run dev` — приложение переключится автоматически.

Выбор бэкенда происходит в одном месте (`src/lib/db/index.ts`); остальной код работает
через интерфейс `DataProvider` и не знает, что под ним.

### Вход через Google

1. В Supabase: **Authentication → Providers → Google**, включить.
2. В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) создать
   OAuth-клиент типа «Web application».
3. В **Authorized redirect URIs** добавить адрес, который Supabase показывает в карточке
   провайдера (`https://<project>.supabase.co/auth/v1/callback`).
4. Client ID и Client Secret вставить в Supabase и сохранить.
5. В **Authentication → URL Configuration** указать Site URL вашего приложения
   (например `http://localhost:5173` для разработки).

Кнопка «Продолжить с Google» на экране входа появится сама — она активна только при
подключённом Supabase, в локальном режиме подсказывает, что нужно настроить.

## Что умеет приложение

### Роли

| | Учитель | Ученик |
|---|---|---|
| Пространства | создаёт курсы и папки | личное пространство + курсы по коду |
| Материалы | загружает, пишет конспекты, добавляет ссылки | смотрит, скачивает, добавляет свои |
| Задания | ставит с дедлайнами, оценивает | сдаёт с комментарием и вложениями |
| Доступ | выдаёт код и права (просмотр/редактирование) | входит по коду или ссылке |
| Прогресс | видит, кто открыл и кто сдал | отмечает «Изучено» |

Роль выбирается при регистрации и меняется в настройках.

### Функционал

- **Библиотека** — сетка или список; карточка = материал или папка: цветная плашка,
  иконка типа, превью текста, теги, автор, дата, звёздочка, меню действий.
- **Загрузка** — перетаскивание в любое место окна или в зону загрузки, несколько файлов
  сразу, превью изображений, прогресс-бар по каждому файлу.
- **Поиск** — капсула в шапке, `⌘K` / `Ctrl+K`, мгновенный результат по названию,
  описанию, тегам, имени файла и **тексту конспектов**.
- **Теги** — пилюли с иконкой в цветном квадрате; клик фильтрует библиотеку; свои теги
  создаются прямо в форме материала (цвет + иконка).
- **Иерархия** — Пространство → папки с вложенностью → материалы; дерево в сайдбаре,
  хлебные крошки в библиотеке.
- **Редактор конспектов** — заголовки, списки, кликабельные чек-листы, выделение, цитаты,
  код, ссылки; автосохранение через 800 мс с индикатором.
- **Задания** — описание, дедлайн, прикреплённые материалы, сдача работы, оценки.
- **Календарь** — месяц и неделя, чипы событий, панель выбранного дня.
- **Просмотрщик** — PDF, презентации, изображения, видео (включая YouTube), аудио и
  конспекты открываются внутри приложения.
- Избранное, личные задачи, приглашения по коду и ссылке, права view/edit, прогресс
  учеников, тёмная тема, скелетоны, пустые состояния, realtime-обновление, адаптив от 360 px.

## Журнал и дневник

Пространство остаётся библиотекой материалов и одновременно работает как школьный журнал —
коды приглашений и структура пространств не меняются.

- **Любая шкала оценивания** — по умолчанию 8-балльная (1–8); в один клик добавляются
  5 / 10 / 12 / 100 баллов, буквенная A–F с GPA, зачёт/незачёт и произвольная: свои уровни,
  пороги в процентах, числовые эквиваленты и цвета. Шкала задаётся пространству и может
  переопределяться для отдельной работы.
- **Критерии оценивания** — учитель добавляет к работе свои критерии со своим максимальным
  баллом (знание материала, аргументация, оформление…). Клетка журнала открывает разбор:
  балл по каждому критерию, живая сумма и процент. В журнал попадает сумма, ученик видит
  разбор в дневнике.
- **Журнал учителя** — сетка «ученики × работы»: клик по клетке и ввод балла, стрелки для
  перемещения, `н` — не был, `осв` — освобождён, правая кнопка — отметка и комментарий.
  Клетка окрашивается по уровню шкалы.
- **Категории и веса** — контрольная, самостоятельная, домашняя, устный ответ, проект.
  Вес категории умножается на вес работы, итог считается взвешенным средним.
- **Учебные периоды** — четверти создаются автоматически; можно завести триместры и модули.
- **Дневник ученика** — средний результат, итоговая отметка, лента оценок с комментариями,
  прогноз «что нужно, чтобы выйти на нужную отметку», сводка посещаемости.
- **Посещаемость** — был / опоздал / не был / уважительная, кнопка «все на месте», проценты.
- **Аналитика класса** — распределение отметок, динамика по работам, самые сложные работы,
  средний результат по категориям, рейтинг учеников.
- **Экспорт CSV** — журнал и посещаемость выгружаются одним файлом.
- **Связь с заданиями** — кнопка «В журнал» в задании создаёт колонку и переносит оценки;
  дальше оценка за сданную работу попадает в журнал автоматически.
- Работы журнала появляются в календаре, сводка — на дашборде.

Миграции журнала: `supabase/migrations/0007_gradebook.sql`, `0008_criteria.sql` и
`0009_lessons_and_bundles.sql` — выполнить после `0006_comments_and_quizzes.sql`.

### Уроки, статусы и важность

- **Уроки.** Отдельный раздел журнала: занятия по датам, у каждого тема, время,
  домашнее задание и заметка учителя. К уроку прикрепляются задания и работы журнала —
  прямо из карточки урока можно завести работу в журнал.
- **Ничего не зашито.** Типы работ и занятий (SA, FA, домашняя, устный ответ, проект,
  лекция), статусы занятия и уровни важности — настраиваемые справочники пространства.
  Меняются имя, короткий код на чипе, цвет, вес в среднем балле, важность по умолчанию
  и участие в итоге. SA и FA — обычные типы: переименовываются и удаляются как любые другие.
- **Статус занятия** меняется одним кликом прямо в карточке урока.
- **Средний балл** — основная метрика вместо процентов: взвешенное среднее в единицах
  шкалы («7 из 8»). Вес работы = вес её типа × собственный вес; типы с выключенным
  «в среднем балле» в расчёт не идут.
- **Оценку можно поправить в любой момент** — и в журнале, и в дневнике: клик по отметке
  открывает разбор с баллом, критериями, отметкой «не был / освобождён» и комментарием ученику.

### Наборы пространств — один код на несколько курсов

Администратор создаёт набор, добавляет в него пространства и раздаёт **один код**:
ученик вводит его один раз и входит сразу во все пространства набора.

Пространство добавляет в набор только тот, кто вправе его редактировать. Чтобы в набор
попало пространство с другого аккаунта, администратор передаёт код его владельцу, а тот
подключает своё пространство кнопкой «Подключить». Так один код открывает курсы разных
учителей, но никто не может раздать доступ к чужому пространству без ведома владельца.

Миграция: `supabase/migrations/0009_lessons_and_bundles.sql`.

## Зеркало на GitHub Pages

Адреса Vercel из России блокируются, поэтому у проекта два деплоя одного и того же бандла:

| Где | Адрес | Роль |
| --- | --- | --- |
| GitHub Pages | `cornflow.me` | основной адрес для пользователей |
| Vercel | `cornflow.vercel.app` | запасной адрес и превью веток |

Сборку зеркала делает `.github/workflows/pages.yml` на каждый пуш в `main`.

Настраивается один раз:

1. **Settings → Pages → Source: GitHub Actions.**
2. **Settings → Secrets and variables → Actions → вкладка Variables** — три переменные
   (не секреты: anon-ключ и так уезжает в браузер):
   `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, при необходимости `VITE_SUPABASE_BUCKET`.
   Значения — те же, что стоят в переменных окружения проекта на Vercel.

   Допускается и одна переменная `KEYS` со строками `ИМЯ=значение` — workflow разберёт её
   сам. Отдельные переменные всё же предпочтительнее: их видно списком и проще править.
3. **DNS домена** — записи `cornflow.me` перевести на Pages:

   ```
   A     @    185.199.108.153
   A     @    185.199.109.153
   A     @    185.199.110.153
   A     @    185.199.111.153
   CNAME www  bin985100-sys.github.io
   ```

   После этого в **Settings → Pages → Custom domain** указать `cornflow.me` и включить
   «Enforce HTTPS» (сертификат выпускается автоматически, обычно за несколько минут).

Файл `public/CNAME` держит домен привязанным к Pages, `public/.nojekyll` отключает Jekyll,
а шаг «SPA fallback» копирует `index.html` в `404.html` — без него перезагрузка страницы
на любом внутреннем маршруте вроде `/app/gradebook` отдавала бы 404.

Важно: если DNS домена остаётся на серверах Vercel (`ns1/ns2.vercel-dns.com`), имя может
не резолвиться из России даже после смены A-записей. Тогда домен нужно перевести на
нейм-серверы регистратора или любого доступного DNS-провайдера.

## Школа: классы, ученики, учителя, МО, предметы, группы

Над пространствами появился уровень **школы**. Пространство осталось курсом —
библиотекой и журналом; школа — это справочник, из которого курсы собираются.
Всё в ней заводит администратор, он же выдаёт логины и пароли.

Управление живёт в отдельной **админ-панели** — `/admin`, у неё свой вход и свой
каркас, без сайдбара приложения, пространств и журнала. Миграции —
`supabase/migrations/0011_school.sql`,
`0012_schools_insert_returning.sql` (чинит политику чтения: при
`INSERT ... RETURNING` она работает как дополнительный WITH CHECK, и проверка
через security-definer функцию не видела только что вставленную строку)
и `0013_departments_and_group_teachers.sql` (МО, учителя группы, учителя курса).

### Что заводится

| Сущность | Из чего состоит |
| --- | --- |
| Параллель | произвольное название: «9», «11», «Начальная школа» |
| Класс | параллель + литера или номер: 9 + А = 9А |
| Ученик | ФИО, класс, логин; учеников может быть сколько угодно |
| Учитель | ФИО, логин |
| МО | методическое объединение: название и цвет; собирает родственные предметы |
| Предмет | МО, название, код, классы где его можно проводить, типы оценивания |
| Группа | ученики + ведущие её учителя; двух типов — см. ниже |
| Курс | предмет × группа × учителя, порождает пространство с журналом |

**Группы двух типов.** Группа класса или параллели — состав ограничен ими,
в список кандидатов попадут только ученики этого класса. Смешанная группа
берёт кого угодно: разные классы, разные параллели.

**МО — методическое объединение.** «Алгебра и начала математического анализа»,
«Геометрия» и «Математика» относятся к МО «Математика». МО ничего не
ограничивает: это группировка, по которой список предметов читается как школьный
учебный план, а не как плоский перечень. Предмет может остаться и без МО.

**Учителя группы.** К группе прикрепляются не только ученики, но и учителя,
которые её ведут, — их может быть несколько. Это ростер группы: при назначении
предмета они подставляются как учителя курса, и админ правит список под конкретный
предмет. Доступ к журналу даёт именно курс, а не ростер, — учитель английского не
получит права в журнале алгебры той же группы.

**Учителя курса.** Один курс могут вести несколько учителей, и журнал у них
**общий**: иначе оценки одной группы разъехались бы по двум журналам, а в дневнике
ученика предмет задвоился бы. Все учителя курса — редакторы его пространства;
снятый с курса доступ теряет, выставленные им оценки остаются. Список правится
кнопкой «Учителя» в строке курса.

**Типы оценивания предмета** — это шаблон. Когда предмет назначают группе,
они переносятся в журнал созданного курса, и учителю не нужно заводить их заново.

### Админ-панель

| Адрес | Что это |
| --- | --- |
| `/admin/login` | вход и регистрация администратора: почта и пароль, без Google и без выбора роли |
| `/admin` | обзор: счётчики, код школы и подсказка, какой шаг следующий |
| `/admin/classes` | параллели и классы |
| `/admin/students`, `/admin/teachers` | люди школы и выдача доступов |
| `/admin/departments` | МО и что в них входит |
| `/admin/subjects`, `/admin/groups`, `/admin/courses` | предметы, группы, назначения |
| `/admin/settings` | название, код школы, выбор школы, удаление |

Регистрация открытая: кто угодно заводит аккаунт, создаёт свою школу и становится
её администратором. Чужие школы ему не видны — RLS отдаёт только те, где он состоит.

Кто вошёл, но администратором ни одной школы не является, видит в панели заглушку
со ссылкой в приложение. Старый адрес `/app/school` ведёт на `/admin`, из сайдбара
приложения пункт «Школа» убран — точка правды одна.

### Аккаунты и вход в школу

Ученик и учитель не регистрируются сами: администратор добавляет их списком
и нажимает «Выдать логины и пароли». Логин предлагается автоматически —
«Иванов Пётр» становится `ivanov.p`; пароль генерируется или задаётся вручную.

Пароли **нигде не хранятся** — их видно только в момент выдачи, поэтому список
сразу можно скачать файлом. Забытый пароль не восстанавливается, но
администратор в любой момент задаёт новый.

Входят на экране `/auth` кнопкой **«Войти в школу»**: код школы, логин, пароль.
Внутри каждому такому аккаунту соответствует служебная почта
`логин@кодшколы.cornflow.school` — письма туда не ходят, она нужна только
Supabase Auth.

### Серверная функция school-accounts

Создание аккаунтов требует прав администратора Supabase, поэтому оно вынесено
в Edge Function `supabase/functions/school-accounts`. Ключ `service_role` живёт
только там — Supabase подставляет его сам через переменную окружения, в браузер
он не попадает никогда.

Развернуть один раз: **Supabase → Edge Functions → Deploy a new function**,
имя `school-accounts`, содержимое — `supabase/functions/school-accounts/index.ts`.
Либо через CLI: `supabase functions deploy school-accounts`.

Функция сама проверяет, что вызывающий — администратор именно этой школы,
и принимает не больше 200 человек за раз (приложение бьёт списки на порции).

В локальном режиме (без Supabase) функция не нужна: аккаунты заводятся прямо
в браузере, всё работает так же.

### Единый дневник ученика

Предметы живут в разных пространствах — так удобно учителю, у каждого свой
журнал. Ученику ходить по ним незачем: `/app/diary` собирает всё на один экран.

- **Сводка** — средний балл сразу по всем предметам и итоговая отметка. Балл в
  единицах шкалы показывается, только если шкала у всех предметов одна;
  иначе честнее процент, а не среднее из разных шкал.
- **Карточка предмета** — средний балл, полоса выполнения, последние отметки
  цветом уровня и переход в полный журнал этого предмета.
- **Домашние задания** — со всех предметов, ближайшие сверху.
- **Лента оценок** — что и когда поставили, с комментарием учителя.

Переключатель «текущий период / весь год» считает период отдельно для каждого
предмета: четверти у курсов свои.

В сайдбаре пункт зависит от роли: учителю «Журнал» текущего курса, ученику
«Дневник» по всем предметам.

### Мои группы — экран учителя

`/app/teaching` отвечает на вопрос «что я веду». Все группы, в которых учитель
преподаёт, разложены **по предметам**: у одного учителя алгебра в трёх группах и
геометрия в двух — это разные курсы и разные журналы, и на экране они разными
блоками. В блоке предмета видно МО, в карточке группы — её тип, число учеников и
коллеги, ведущие тот же курс. Клик по карточке открывает журнал этой группы.

Экран строится из курсов, а не из ростера группы: учитель видит то, что ему
назначено, и ничего лишнего. Пункт «Мои группы» в сайдбаре показывается только
учителю.


## Логотип и вход через Google

Знак — колонна и раскрытая книга. **Без подложки: фон везде виден насквозь.**

Рисунок хранится в двух вариантах, и это не прихоть. Исходник светлый —
розовый и кремовый, — он отлично читается на тёмном, но на белом кремовые
части (колонна и книга) сливаются с фоном, остаётся розовый призрак. Поэтому
для светлых поверхностей тот же рисунок перекрашен в тёмно-сливовый с розовыми
акцентами: силуэт тот же, читаемость возвращается. Компонент `Logo` выбирает
вариант сам — по теме приложения, а на цветных и тёмных фонах (`tone="light"`)
всегда берёт исходный.

| Файл | Где используется |
| --- | --- |
| `logo-mark.png` | знак на тёмном: тёмная тема, шапка лендинга, экран входа |
| `logo-mark-light.png` | знак на светлом: светлая тема, Open Graph |
| `logo-mark-192.png`, `logo-mark-light-192.png` | мелкие размеры |
| `apple-touch-icon.png` | иконка на домашнем экране iOS |
| `favicon.svg` | вкладка браузера, сам меняется по теме системы |
| `logo-google-120.png` | логотип для экрана входа Google (120×120) |

Фавиконка — SVG с двумя картинками внутри и медиазапросом
`prefers-color-scheme`: на светлой панели вкладок показывается сливовый
вариант, на тёмной — розовый. Растровая иконка так не умеет, поэтому здесь
именно SVG.

### Экран выбора аккаунта Google

Google показывает там не наш сайт, а хост, на который возвращает пользователя,
— то есть адрес проекта Supabase. Меняется это в двух местах, и только одно из
них бесплатное.

**Название и логотип** — Google Cloud Console → APIs & Services → OAuth consent
screen → Branding: имя приложения `CornFlow`, логотип `logo-google-120.png`,
домашняя страница `https://cornflow.me`, в Authorized domains — и `cornflow.me`,
и `supabase.co`. Логотип показывается после проверки приложения Google.

**Сам домен в строке «Переход в приложение…»** берётся из адреса возврата, а он
у нас на `*.supabase.co`. Чтобы там стояло `cornflow.me`, нужен платный
custom domain у Supabase (около $10 в месяц): поддомен вида `auth.cornflow.me`
прописывается адресом возврата в Google OAuth, и экран начинает называть наш
домен.

## Когда сервер не отвечает

Клиент Supabase не ставит таймаут на запросы: если бэкенд молчит — проект на
паузе, сбой сети, — промис висит вечно, и приложение застревает на сплэше.
Поэтому первая проверка сессии ограничена 12 секундами, и по её истечении
вместо бесконечной загрузки показывается экран «Не удаётся связаться с
сервером» с кнопкой «Повторить». На экране входа сетевая ошибка тоже отделена
от неверного пароля — иначе подсказка про «три причины» только путает.


## Проект Supabase не должен засыпать

На бесплатном тарифе Supabase ставит проект на паузу, если за 7 дней к базе
почти не обращались. Снаружи это выглядит так: лендинг открывается (он
статический), а приложение висит на загрузке или пишет, что сервер не
отвечает, — и поднимать проект приходится руками в дашборде.

Лечится тем, что к базе кто-то регулярно обращается: по документации
достаточно нескольких запросов в день. Для этого заведены две вещи:

- `supabase/migrations/0014_heartbeat.sql` — таблица `heartbeat` с одной
  строкой и функция `touch_heartbeat()`. Читать таблицу может кто угодно,
  писать — никто: отметка времени ставится только через функцию, поэтому
  точки, где аноним пишет в базу напрямую, не появляется.
- `.github/workflows/keepalive.yml` — раз в сутки дёргает `touch_heartbeat()`
  ключом, который и так уезжает в браузер. Это настоящая запись в базу, а не
  просто HTTP-ping. Если функции ещё нет, шаг откатывается на обычное чтение.
  Когда база не отвечает вовсе, workflow падает — это ранний сигнал, что
  что-то не так, задолго до жалоб пользователей.

Чего это **не** гарантирует. GitHub отключает расписание в репозиториях, где
60 дней не было коммитов: тогда workflow надо один раз запустить кнопкой
Run workflow. И пауза отменяется совсем только на платном тарифе Supabase —
там проекты не засыпают по определению. Бесплатный вариант держит проект
живым, пока живы обе половины: репозиторий и расписание.
